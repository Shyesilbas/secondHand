# Escrow Domain

Holds buyer purchase funds in custody (`escrows` table, one row per `OrderItem`) upon checkout and either releases them to the seller's eWallet via transactional outbox + Kafka after delivery completion, or refunds them to the buyer on order cancellation/refund.

## Business Rules & Invariants
- **Item-Level Escrow Ledger (`EscrowService.hold`):** Writes one `Escrow` row per `OrderItem` (unique on `order_item_id`) with net post-campaign/post-coupon `amount`, audit snapshot fields (`listingTitle`, `listingNo`), and `PaymentStatus.ESCROW`, then evicts the buyer's and sellers' `payment:stats` entries. Never create a second `payments` row to represent the hold.
- **Platform Coupon Subsidy (`Escrow.platformSubsidy`):** `hold` copies `OrderItem.couponDiscount` into `platform_subsidy`; `amount` stays the buyer-paid net. Release pays the seller `Escrow.sellerPayout()` (`amount + platformSubsidy`) through `EscrowOutboxService`; refund and cancel return only `amount`. Seller earnings sums (`sumSellerAmountsByOrderIds`, `EscrowRepository`) use the same payout. Seller campaigns are the only discount that lowers the payout, together with the commission below.
- **Pre-Release Refund Boundary (`EscrowService.refund`):** Reversals to `PaymentStatus.REFUNDED` (crediting the buyer's eWallet) are permitted only while in `PaymentStatus.ESCROW`. Once released to `COMPLETED`, funds belong to the seller and cannot be clawed back via escrow.
- **Outbox-Decoupled Seller Payout (`EscrowService.releaseEscrowForOrder`):** Order completion marks `Escrow` rows `PaymentStatus.COMPLETED` (`releasedAt = now()`) and enqueues an `ESCROW_RELEASED` event into `escrow_outbox_events` in the same ACID transaction without mutating the seller's wallet synchronously.
- **Fail-Loud Idempotent Consumer (`EscrowKafkaConsumer`):** Consumes `escrow.released.v1`, validates required event fields (`PaymentErrorCodes.ESCROW_RELEASE_EVENT_INVALID` routes malformed events to `escrow.released.v1.DLT` after retries), deduplicates via `ProcessedKafkaEventRepository` (`escrow:release:{escrowId}` in `processed_kafka_events`), and credits the seller via `IEWalletService.creditWalletQuietly`.
- **Seller Commission (`CommissionService`):** `hold` stores `commission_amount` and `commission_rate` per item from the seller gross (`amount + platformSubsidy`): bands from `app.platform.commission.bands` (`PlatformFeeConfig`, 1-999,99 at 7%, 1000-9999,99 at 6%, 10000+ at 4%), HALF_UP to 2 decimals. No commission for fee-bearing listing types (`ListingType.chargesCreationFee`), for orders created before `app.platform.commission.effective-from`, or for a zero gross. `Escrow.sellerPayout()` is `sellerGross() - commissionAmount`; refund and cancel are unaffected (the buyer gets `amount` back, the commission is never taken).
- **System Account Settlement (`EscrowKafkaConsumer.settleSystemAccount`):** `EscrowReleasedKafkaEvent` carries `amount` (seller payout), `platformSubsidy` and `commissionAmount`. After crediting the seller the consumer credits the system wallet `commission - platformSubsidy` in one signed move; the system balance may go negative and never delays the seller payout.
- **Shipping Fee Refund (`EscrowService.refundShippingFee`):** called from `OrderCancellationService.finalizeCancellation` when every item is cancelled; credits the buyer `Order.shippingFee` as a `REFUND` and debits the system wallet, once (`shipping_fee_refunded`). Partial cancellations never refund it.
- **Free Shipping Deduction (`EscrowService.allocateShippingDeduction`):** when `Order.sellerShippingCharge` is set (cargo order whose goods total reached `app.platform.shipping.free-threshold`), `hold` splits it across the order's items by seller gross (last item takes the rounding remainder, each share capped at the item gross) into `escrows.shipping_deduction`. `Escrow.sellerPayout()` subtracts commission and deduction; the event carries `shippingDeduction` and the consumer credits it to the system account with the commission. A cancelled item drops its share; a fully cancelled order never releases, so nothing is deducted.
- **Change rule:** Refunds are possible only while the escrow row is unreleased, and always go to the buyer. Never refund `platformSubsidy` or the commission and never pay the seller `amount` alone for a coupon order; use `sellerPayout()`. `EscrowService.sellerEarningsByOrderIds` returns gross, commission and payout per order for seller views.

## Redis, Outbox & Kafka
- Cache eviction: `PaymentStatsCacheEvictor` drops the buyer's and seller's `payment:stats` entries on every escrow state change (after commit).
- Outbox: `escrow_outbox_events`, polled by `EscrowOutboxWorker` (`app.escrow.outbox.fixed-delay-ms`).
- Kafka topic: `escrow.released.v1` (`EscrowReleasedKafkaEvent`), consumed by `EscrowKafkaConsumer`.
